# React Native/Expo Review

## Validation

- `npm run lint` passed.
- `npx tsc --noEmit` passed.
- The app was not launched in an Expo simulator or on a device during this review.

## Findings

1. **[FAIL] — Daily inspiration does not change while the app remains open across midnight.** `AppDataProvider` performs the date selection only when it mounts ([AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:71)), and it has no timer or app-state/date check to refresh `dailyEntry`. It also does not recalculate when the app becomes active after midnight. This fails the requirement that the entry change on the next calendar day; it only reliably changes after a provider remount/restart ([SPEC.md](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/SPEC.md:85)).

2. **[FAIL] — Mutation functions use stale state snapshots and can lose or duplicate writes.** `addEntry`, `toggleFavorite`, and `addManifestation` build the next collection from the closure's current `entries` or `manifestations` ([AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:139), [AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:159), [AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:167)). Rapid repeated taps can invoke them before React rerenders. Separate snapshots can overwrite each other in AsyncStorage, and repeated favorite taps can persist the same toggled state rather than alternating. Save buttons should also be disabled or guarded while writes are in progress.

3. **[WARN] — Stored JSON is not validated or partially recovered.** The provider assumes every stored value parses and matches the entity shapes ([AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:82)). Malformed JSON or old/incomplete objects can cause the whole load to report a generic reflection error, leave partial state, or create runtime issues in date sorting and rendering. Validation and migration of stored data would make reopened-app behavior more reliable.

4. **[PASS] — Daily inspiration selection is deterministic and persistent.** The selector hashes the local date plus entry ID and excludes favorite status ([AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:35), [AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:51)). The date and ID are written to AsyncStorage for the day ([AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:91)). A valid same-day selection is reused after reopening; a different date or missing entry is replaced with a deterministic choice.

5. **[PASS] — The home empty state is implemented correctly.** When loading finishes and no entry exists, the home screen displays a welcoming message and a first-entry action ([index.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/index.tsx:34), [index.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/index.tsx:48)).

6. **[PASS] — Past entries are sorted by favorite status and newest created date.** The home screen separates favorites first and sorts both groups by `createdAt` descending ([index.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/index.tsx:11)). The derived array is updated whenever entry state changes, so favorite changes reorder the list automatically.

7. **[PASS] — The daily inspiration title opens the full entry.** The inspiration card routes to `/journal` with the entry ID ([index.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/index.tsx:39)), and the journal screen resolves that ID and renders the title, reflection, and creation date ([journal.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/journal.tsx:10), [journal.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/journal.tsx:51)).

8. **[PASS] — Journal creation, required-field validation, and trimming are implemented.** The create form asks for a title and “What I Learned,” alerts on missing or whitespace-only values, and trims values before saving ([journal.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/journal.tsx:18), [AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:139)).

9. **[PASS] — Saved journal entries include all required entity fields.** Each entry has a unique ID, trimmed title and reflection, ISO creation date, and `isFavorite: false` ([AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:140)).

10. **[PASS] — Favorite/unfavorite works on both required screens.** The home list and journal detail screen expose the star action, use filled/outlined symbols, and call `toggleFavorite` ([index.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/index.tsx:84), [journal.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/journal.tsx:37)). AsyncStorage writes persist the status on reopening ([AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:159)).

11. **[PASS] — Journal entries and manifestations use AsyncStorage collections.** The provider uses distinct keys for entries and manifestations ([AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:29)) and reloads both on mount ([AppDataContext.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/storage/AppDataContext.tsx:74)).

16. **[WARN] — Dark-mode support is inconsistent.** The layout supplies a dark navigation theme ([_layout.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/_layout.tsx:8)), but every screen uses fixed cream, white, and gray `StyleSheet` values ([index.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/index.tsx:108), [journal.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/journal.tsx:95), [manifestations.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/manifestations.tsx:72)). This is not a stated acceptance criterion, but the app will not provide intentional dark-mode appearance.

17. **[WARN] — Several controls have incomplete accessibility metadata.** The back buttons, entry list main pressables, and some save controls lack explicit `accessibilityRole` or meaningful labels ([journal.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/journal.tsx:34), [manifestations.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/manifestations.tsx:30)). The star and top-level action buttons do have labels or roles. Adding consistent metadata would improve VoiceOver/TalkBack usability.

18. **[WARN] — Text inputs lack mobile keyboard composition safeguards.** Both screens disable no keyboard behavior; notably, multiline inputs are not wrapped in `KeyboardAvoidingView` or given explicit return/submit behavior ([journal.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/journal.tsx:64), [manifestations.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/manifestations.tsx:37)). On shorter phones or when a keyboard is open, the save control may be covered.

19. **[WARN] — There is no in-flight write state or cleanup of stale route parameters.** Save and favorite actions do not expose loading/disabled state ([journal.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/journal.tsx:83), [manifestations.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/manifestations.tsx:47)). Also, an unknown or stale journal `id` renders the journal screen as a new-entry form because `entry` becomes undefined ([journal.tsx](/Users/nicoletimko/Desktop/cmu_year3/codingAI/my-app/src/app/journal.tsx:10)); an invalid deep link should have an explicit not-found state or redirect.
